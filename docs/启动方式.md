# 启动方式

## 环境要求

- Python 3.12+（已在 3.14 验证）
- Node.js 18+
- 无需安装 MySQL / Redis（开发模式默认 SQLite + 进程内存储）

## 一、启动后端（端口 8001）

```powershell
cd kaoyan-rbac\backend
pip install -r requirements.txt        # 仅首次
python -m uvicorn app.main:app --host 127.0.0.1 --port 8001
```

启动时自动完成：

1. 读取 `.env` 配置
2. 自动建表（SQLite 文件 `backend/app_local.db` 会自动生成）
3. 幂等写入种子数据：2 个角色、16 条权限、初始管理员 `admin` / `Admin@123456`
4. 邮件走 QQ SMTP 真实发信；失败时降级为控制台回显验证码（看终端日志 `[DEV]` 字样）

验证：

- Swagger 文档：http://127.0.0.1:8001/docs
- 数据库自检：http://127.0.0.1:8001/api/db-check （应返回 `"成功连接 SQLite"`）

## 二、启动前端（端口 5173）

另开一个终端：

```powershell
cd kaoyan-rbac\frontend
npm install        # 仅首次
npm run dev
```

访问 http://localhost:5173 。`/api` 请求由 Vite 自动代理到 8001，无需额外配置。

## 三、验证账号

| 账号 | 密码 | 说明 |
|------|------|------|
| `admin` | `Admin@123456` | 系统管理员，左侧可见 用户管理/角色管理/审计日志 |
| 自行注册 | — | 注册后默认「考研学生」角色，管理菜单不显示 |

邮箱验证码登录：在登录页切到「邮箱登录」，输入注册邮箱收验证码（真实邮件，注意垃圾箱）。

## 四、在其他设备上运行（新机器完整流程）

适用于把项目拷贝/克隆到另一台电脑（Windows / macOS / Linux 均可）。

### 1. 准备环境

| 软件 | 版本 | 说明 |
|------|------|------|
| Python | 3.12+ | 后端运行 |
| Node.js | 18+ | 前端构建/运行 |
| MySQL / Redis | 无需安装 | 默认 SQLite + 进程内存储 |

### 2. 拷贝项目

整个 `kaoyan-rbac/` 目录拷过去即可。建议**排除**以下目录（到新机器重建，体积也小）：

```
backend/app_local.db      # 本地数据库（新机器首次启动自动重建+播种）
backend/__pycache__/
frontend/node_modules/
frontend/dist/
```

### 3. 后端

```bash
cd kaoyan-rbac/backend
python -m venv .venv                # 建议虚拟环境
# Windows: .venv\Scripts\activate    macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
python -m uvicorn app.main:app --host 0.0.0.0 --port 8001
```

- `.env` 必须一起拷贝（含 SECRET_KEY 与邮箱配置）；如未拷贝，按 `docs/脚手架配置说明.md` 的 `.env` 关键项重新创建
- `--host 0.0.0.0` 允许局域网内其他设备访问；仅本机用则保持 `127.0.0.1`

### 4. 前端

```bash
cd kaoyan-rbac/frontend
npm install
npm run dev -- --host               # --host 允许局域网访问
```

- 跨设备访问时：浏览器打开 `http://<后端机器IP>:5173`
- 若前端与后端不在同一台机器，改 `vite.config.ts` 的代理目标为后端机器 IP，并重启 dev server

### 5. 生产部署提示

- `APP_ENV=production` 后会自动关闭 Swagger 以外的调试面（`/api/db-check`、`/static/file_test.html`、验证码回显均失效）
- 生产必须：`USE_SQLITE=false` + 配置 MySQL；`REDIS_ENABLED=true` + 真实 Redis（多进程部署必须，否则登录锁定/令牌吊销不生效）；`MAIL_FALLBACK_CONSOLE=false`
- 数据库结构稳定后建议引入 alembic 迁移替代自动建表

## 五、常见问题

| 现象 | 处理 |
|------|------|
| 8001 端口被占用 | 改 `.env` 的 `BACKEND_PORT` 并用 `--port` 启动，同时改前端 `vite.config.ts` 代理目标 |
| 收不到验证码邮件 | 看后端终端：SMTP 失败会降级回显验证码（开发环境）；检查授权码是否过期 |
| 登录提示"失败次数过多" | 锁定 10 分钟，或用忘记密码重置（重置成功会自动解除锁定） |
| 想换 MySQL | `.env` 设 `USE_SQLITE=false` 并配置 `DB_HOST/DB_PORT/DB_USER/DB_PASSWORD/DB_NAME` |
| 删库重来 | 停止后端，删除 `backend/app_local.db`，重启即可自动重建并重新播种 |
