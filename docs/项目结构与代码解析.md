# 项目结构与代码解析

> 项目：kaoyan-rbac（考研AI导学平台，rjgc 的鉴权框架重写版）
> 后端 FastAPI + SQLAlchemy 2.x + AuthX(JWT) + argon2；前端 Vue 3 + Vite + TypeScript + Element Plus + Pinia
> 本文覆盖：目录结构、逐文件代码解析、各项设计的实现方式与流程。

## 第二部分 后端代码解析

### 1. 启动流程（main.py 的 lifespan）

```
校验 SECRET_KEY/Redis 配置 → AUTO_CREATE_TABLES 建表 → AUTO_SEED 播种 → 数据库探活
```

- `create_all()` 先 `import app.models` 注册全部 mapper，再 `Base.metadata.create_all`，幂等
- `seed_rbac()` 幂等写入：角色（考研学生 id=1 / 系统管理员 id=2）、16 条权限、授权关系（学生 7 条、管理员全量）、初始管理员 `admin`（已存在则跳过，不改密码）
- 生产环境下 `/api/db-check` 与 `/static/file_test.html` 直接 404

### 2. 统一响应与异常（exceptions.py）

所有错误走 `AppError`（status_code + message）层级：`BadRequestError(400)` / `UnauthorizedError(401)` / `ForbiddenError(403)` / `NotFoundError(404)` / `ConflictError(409)`。全局处理器把 AppError 转成 `{code, message, data}`；`RequestValidationError` 转 422 并取首条错误拼成「字段: 原因」；未知异常转 500 并记日志。前端因此只需处理一种错误格式。

### 3. 配置（config.py）

普通类 + `os.getenv`（python-dotenv 加载 `.env`），无 pydantic-settings 依赖。关键派生属性：

- `database_url`：`USE_SQLITE=true` → `sqlite:///./app_local.db`；否则拼 MySQL 连接串
- `is_production`：驱动 db-check 404、验证码回显禁用等安全开关
- `mail_configured` / `mail_fallback_allowed`：邮件通道是否可用/是否允许控制台兜底（生产禁止回显）

### 4. 令牌设计（security.py + deps.py）——三个独立机制叠加

| 机制 | 实现 | 解决什么 |
|------|------|----------|
| JWT 本身 | AuthX 1.7.1，HS256，`sub=user_id`，过期时间 1440 分钟可配 | 无状态会话凭证 |
| 吊销名单 | `revoke_token()` 把 token 的 **SHA-256 摘要**写入 KV（`auth:revoked:<sha256>`），TTL 与令牌同寿；AuthX blocklist 回调 `_is_revoked` 命中即拒 | 退出登录立即失效（改造前 JWT 无法吊销） |
| 密码版本 pv | 令牌载荷带 `pv` 自定义 claim；改密/重置时 `bump_password_version()` 使 KV 中 `auth:pwdver:<uid>` +1；每个请求比对令牌 pv 与当前版本 | 改密后旧令牌全部失效，无需逐个吊销 |

`get_current_user` 完整校验链（deps.py）：

```
取 Bearer → 吊销名单检查 → AuthX 验签/过期 → sub 转 user_id → 用户存在? → account_status=1? → pv 一致? → 放行
```

任何一步失败抛 401/403，由统一异常处理器输出。原始 token 挂在 `request.state.access_token` 供 logout 使用。

### 5. 密码安全（security.py）

- **argon2-cffi** 慢哈希 + 随机盐，单条约 96 字符，存 `sys_user.password VARCHAR(128)`
- **哑哈希** `verify_password_dummy()`：账号不存在时也执行一次等代价校验，防响应时间枚举账号
- **强度校验**：8-64 位且必须字母+数字（注册、重置、改密三处统一调用 `validate_password_strength`）
- **邮箱脱敏** `mask_email()`：`z*******n@qq.com`，用于日志、审计、接口响应

### 5.1 图形验证码人机验证（core/captcha.py）

- **生成**：4 位随机字符（去除 0/O/1/I 易混淆字符），随机旋转/位置/颜色 + 噪声线噪点，SVG 字符串拼接，无第三方绘图依赖；`GET /api/user/captcha` 返回 `{captcha_id, svg, expires_in}`，前端 `v-html` 渲染、点击刷新
- **存储与校验**：答案小写存 KV（`captcha:{id}`，300 秒过期）；**一次性**——无论对错立即作废防重放；不区分大小写，`hmac.compare_digest` 比对
- **触发规则**：密码登录连续失败 `CAPTCHA_AFTER_FAILURES`（默认 2）次后强制要求，复用登录锁定的三维度计数键（输入标识/用户名/user_id），换标识无法绕过
- **校验时机**：闸门在哑哈希/验密之前；**只要请求携带验证码字段就必须校验**（前端首次失败即展示验证码框，此时计数未必到阈值，不校验则形同虚设）；缺失或错误返回 `code=40010`，前端据此展示并刷新验证码

### 6. 登录安全流程（modules/user/service.py）

**密码登录 `authenticate()` 顺序**：

```
锁定检查(输入标识) → 按用户名或邮箱查用户 → 查到则再按 user_id 维度查锁定
  → 图形验证码闸门(失败满 2 次强制; 只要带了验证码字段就必须校验)
  → 不存在: 哑哈希 + 计一次失败 + 审计 → 统一报「账号或密码错误」
  → 存在: argon2 验密 → 错则计失败 + 审计 → 同样提示
  → 账号被禁用 → 403
  → 成功: 清三处失败计数 + 审计 → 返回用户
```

**失败锁定的三维度设计**（`_lock_keys`）：输入字符串、用户名、user_id 各一把计数键，共享同一额度——防止「用户名试 5 次再换邮箱试 5 次」绕过锁定。阈值 5 次、锁定 600 秒（达到阈值时直接抛锁定提示而非密码错误）。登录成功或重置密码成功时三处一起清。

**邮箱验证码 `send_email_code()` / `_consume_code()`**：

- 生成 `secrets.randbelow(1000000)` 补足 6 位
- 存 KV：`email:code:{purpose}:{email}` = `{code, attempts:0}`，TTL 300 秒；冷却键 `email:code:cooldown:...` TTL 60 秒，存在即报「发送太频繁，请 N 秒后再试」
- 校验用 `hmac.compare_digest` 防时序比较；错 1 次 attempts+1（保留原 TTL），错满 5 次作废；**验过即删，一次性，不可重放**
- 无论邮箱是否注册都返回同样的提示，防账号枚举
- 邮件走 QQ SMTP（SSL 465 + 授权码），HTML 模板 + 纯文本兜底双格式；发信失败且非生产 → 降级控制台回显（响应 `channel=console` 带 `dev_code`），生产强制 503

**重置/修改密码**：重置密码用验证码（purpose=reset）→ 改哈希 → **pv+1**（旧令牌全失效）→ 清登录锁定。登录后改密需验原密码、新密码不得与原密码相同，改完 pv+1 且当前令牌也吊销。

### 7. RBAC 鉴权（core/rbac.py）

- **模型**：`sys_user ↔ sys_user_role ↔ sys_role ↔ sys_role_permission ↔ sys_permission`，两张中间表带联合唯一约束与外键级联删除
- **超管放行**：`is_super_admin()` 判断用户角色 ∩ `admin_role_ids`（默认 role_id=2），命中直接拥有全部权限
- **权限缓存**：`user_permission_keys()` 结果存 KV，key 为 `rbac:perm:{全局版本}:user:{id}`；任何角色/权限变更只 `invalidate_permission_cache()` 把全局版本 +1，旧缓存自然失效，无需扫描删除
- **依赖工厂**：`require_permission("role:manage")` 生成 FastAPI 依赖，路由上 `Annotated[User, Depends(require_permission(...))]` 一行接线，无权抛 403。**权限只在服务端判定，前端隐藏只是体验优化**

### 8. 管理端（modules/rbac/）

11 个端点全部挂 `require_permission`：角色 CRUD、角色授权查询/覆盖保存、权限清单按模块分组、用户分页列表（含角色）、分配角色、启用/禁用账号、审计日志分页（时间倒序）。授权变更会写审计并触发权限缓存失效。

### 9. 审计（core/audit.py）

`write_audit()` 统一落 `sys_audit_log`：动作枚举（注册/登录成功/登录失败/重置密码/改密/退出/授权变更等）、操作人、目标类型与 ID、detail JSON、来源 IP、成功与否。登录失败会区分 `unknown_account` / `bad_password` 等原因码（对用户仍统一提示）。

### 10. 数据表一览

| 表 | 说明 | 关键点 |
|----|------|--------|
| sys_user | 登录账号 | login_name/email 唯一索引；password 存 argon2；account_status TINYINT |
| user_account | 业务画像 | 与 sys_user 一对一，级联删除 |
| sys_role | 角色 | role_name 唯一 |
| sys_permission | 权限 | perm_key 唯一，格式 `模块:操作`，module_name 用于分组 |
| sys_user_role / sys_role_permission | 中间表 | 联合唯一约束 + 外键 CASCADE |
| sys_audit_log | 审计 | 追加只读 |
| chat_session / upload_file / study_plan | 业务占位 | 接入真实业务时替换 |

## 第三部分 前端代码解析

### 1. 请求层（utils/request.ts）

axios 实例 `baseURL: '/api'`（Vite 代理到 8001）。请求拦截器注入 `Authorization: Bearer <token>`；响应拦截器统一解包 `{code,message,data}`，失败时 ElMessage 提示后端 message；**401 时清本地 token/user 并跳 `/login?redirect=<当前路径>`**。axios v1 泛型经 `unwrap<T>()` 辅助函数强转，保住类型。

### 2. 登录态（stores/auth.ts）

- state：`token` / `user` / `roles` / `permissions`，持久化到 localStorage（`kaoyan_token` / `kaoyan_user`）
- 登录成功后一次性写入 token + 用户 + 角色 + 权限（后端登录响应已带全，无需额外请求）
- `hasPerm(key)`：界面过滤的唯一入口；`isAdmin`：角色含「系统管理员」
- `restore()`：刷新页面后从 localStorage 恢复，并 `fetchProfile()` 拉最新权限（后台改授权后前端能感知）
- `logout()`：先调后端吊销令牌，再清本地状态

### 3. 权限三件套（「未授权不显示」的实现）

1. **菜单**：`config/menu.ts` 每项带 `perm`，DefaultLayout 渲染时按 `hasPerm(item.perm)` 过滤，业务菜单与后台管理菜单分组渲染
2. **路由**：`routes.ts` 中路由 `meta: { requiresAuth, perm }`；全局守卫：未登录 → `/login`；已登录但权限缺失 → 先 `fetchProfile()` 再判断，仍无权限则提示并回首页
3. **按钮**：`v-permission="'role:manage'"` 指令，mounted 时查权限，无权限直接 `el.remove()`（DOM 移除而非隐藏）

三者都是体验层；真正的边界是服务端 403。

### 4. 页面

- **LoginView**：密码登录 / 邮箱验证码登录双 Tab；发码按钮 60 秒倒计时（对齐后端冷却）；密码登录失败后展示图形验证码（输入框 + SVG 点击刷新），提交带 `captcha_id`/`captcha_code`；登录成功按 redirect 跳回
- **RegisterView**：用户名/邮箱/密码的格式与强度实时提示（与后端规则一致）
- **ProfileView**：个人信息查看与修改（昵称/本科专业/目标专业/地区/备考阶段/目标分数）、修改密码
- **admin/RoleManageView**：角色 CRUD + 权限勾选树（按模块分组），保存后后端触发权限缓存失效
- **admin/UserManageView**：用户分页列表、分配角色、启用/禁用开关
- **admin/AuditLogView**：审计日志分页查看

## 第四部分 关键流程时序

### 密码登录

```
前端 → POST /api/user/login {username, password [, captcha_id, captcha_code]}
后端 → 锁定检查 → 查用户(用户名/邮箱)
     → [失败满 2 次且无验证码] 40010 → 前端展示图形验证码
     → [带了验证码] 校验(一次性, 错/缺均 40010)
     → [无此人] 哑哈希+计失败 → 401 统一提示
     → [有] argon2 验密 → [错] 计失败 → 401 统一提示
     → 禁用? → 403
     → 清失败计数 + 审计 → 签发 JWT(含 pv) → {token, user, roles, permissions}
前端 → 存 localStorage → 菜单按权限过滤渲染
后续请求 → 携带 Bearer → get_current_user 五重校验 → require_permission 鉴权
```

### 邮箱验证码登录

```
POST /api/user/email-code {email, purpose:"login"}
  → 冷却检查(60s) → 生成 6 位码存 KV(300s) → QQ SMTP 真实发信(失败降级控制台)
用户收邮件 → POST /api/user/login/email {email, code}
  → 消费验证码(一次性, 错 5 次作废) → 查用户 → 锁定检查 → 签发 JWT
```

### 忘记密码

```
POST /api/user/email-code {email, purpose:"reset"} → 收码
POST /api/user/password/reset {email, code, new_password}
  → 强度校验 → 消费验证码 → 改 argon2 哈希 → pv+1(旧令牌全失效) → 清登录锁定
→ 新密码重新登录
```

### 退出登录

```
POST /api/user/logout → token SHA-256 写入吊销名单(TTL=令牌剩余寿命) → 前端清本地态
该 token 再访问任何接口 → 吊销名单命中 → 401
```

## 附：设计决策速查

| 决策 | 选择 | 理由 |
|------|------|------|
| 令牌吊销 | KV 存 SHA-256 摘要 | 不落原始 token；TTL 与令牌同寿自动清理 |
| 改密失效 | pv 密码版本号 | 不加数据库列、不逐个吊销，一次 incr 全部失效 |
| 权限缓存 | 全局版本号失效 | 变更 O(1)，无需扫描删除用户缓存 |
| 防账号枚举 | 统一提示 + 哑哈希 + 验证码场景不区分邮箱是否存在 | 响应内容与耗时都不泄露 |
| 失败锁定 | 用户名/邮箱/user_id 三键共享额度 | 防换标识绕过 |
| 图形验证码 | 失败 2 次后强制；提交即校验、一次性 | 防机器人爆破；前端提前展示时不校验会形同虚设 |
| Redis 降级 | 进程内内存 | 离线可演示；多 worker 部署必须用真 Redis |
| 邮件降级 | 仅开发环境允许回显 | 生产回显等于验证码失效 |
| ORM 属性名 | 保留 id/username/password_hash，列名映射到 sys_user 规范 | 既有业务模块代码零改动 |
